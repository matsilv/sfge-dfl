# Tests

The `tests/` folder holds a `unittest` suite that checks data generation, data loading, the optimization problems and
the training pipeline for each problem.

## Running the tests

Run every command from the repo root, so that the relative paths (`data/data/...`, `tests/<problem>/...`) and the
absolute imports resolve:

```
python -m unittest discover -s tests -t . -v      # whole suite
python -m unittest tests.test_knapsack -v         # one module
```

A Gurobi license is required. The license bundled with the pip `gurobipy` package only solves small models.

## What each module does

| Module | Content |
|---|---|
| `test_knapsack`, `test_quadratic_kp`, `test_stochastic_capacity_kp`, `test_stochastic_weights_kp`, `test_wsmc` | Generate a small dataset in `data/data/`, check the saved instances, the optimization problem and the data loader, then train a few methods with `tests/<problem>/config.json`. Some modules also compare the logged metrics with the reference ones in `tests/<problem>/sanity-check/`. |
| `test_pto_plus_saa` | Trains an MLE model on each stochastic problem and runs PFL + Sample Average Approximation on top of it (`tests/<problem>/saa_config.json`). It needs the datasets generated by the stochastic KP and WSMC modules. |
| `test_fractional_kp` | Skipped unless the fractional KP dataset has been copied into `data/data/fractional_kp` by hand (there is no generation script for it). |

Tests within a module are numbered and must run in order: later tests use the data and results produced by earlier
ones.

## Outputs

Training results are written to `tests/<problem>/results/` and `tests/<problem>/results-saa/`. Both folders are
git-ignored and are removed at the start of each run.
